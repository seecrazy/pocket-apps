# SoloGuard 设计文档

> 状态：已采纳
> 版本：1.2.0
> 更新时间：2026-11-14

## 1. 产品定位

SoloGuard 不做紧急联系人外发，也不上传生活状态。它把“今天正常吗”变成一个低压力、可回看的本地仪式，帮助独居用户观察自己的日常节奏。

**副标题**：独居守护
**Bundle ID**：`com.pocketapps.sologuard`

### 目标

- 用一个清晰的核心动作解决真实场景。
- 数据只保存在本机，隐私边界在首启说明中说清楚。
- UI 能表达空态、进行中、完成、失败和恢复状态。
- 单元测试覆盖核心状态机和过滤器。
- 不把业务逻辑泄漏到共享 Package。

### 非目标

- 不做云后端。
- 不做账号体系和跨设备自动同步。
- 不引入和核心体验无关的复杂权限。
- 不做广告、推荐或数据采集。

## 2. 用户与真实场景

用户早上或晚上打开 App，点一下“完成签到”。连续 5 天后，App 用连续计数给用户一个稳定的心理锚点；如果昨天没有签到，会给出明确的“昨日已错过”提示。

### 典型流程

1. 首启说明 → 创建计划 → 每日提醒或手动签到 → 签到历史回看。
2. 关闭计划时取消本地通知，但保留手动签到能力。
3. 删除计划时取消提醒、清理记录，并使用确认弹层避免误删。

## 3. 信息架构

三栏 Tab：**今日**、**历史**、**设置**。首启说明在首次进入 App 时以全屏页呈现。

## 4. 数据模型

- `CheckInPlanModel`：计划 ID、标题、提醒时间、启用状态、创建时间。
- `CheckInRecordModel`：签到记录 ID、计划 ID、日期、完成时间、备注。

## 5. 关键交互与状态

- 计划：`enabled` / `disabled`
- 今日签到：`waiting` / `completed`
- 历史记录：`completed` / `missed`
- 连续计数：从今天向前回溯本地日历中的连续完成日。

关闭计划时取消通知；删除计划时取消通知并清理记录。

## 6. 错误与边界处理

- **提醒权限被拒绝：保留手动签到，仍可查看历史。**
- **时区或日期边界：以本地日历的 `startOfDay` 计算连续记录。**
- **用户误删：破坏性操作必须有确认。**

## 7. 隐私与数据边界

- 计划与签到记录保存在本机 SwiftData。
- 本地通知仅用于提醒用户确认。
- 不上传生活状态，不联系紧急联系人。

## 8. 测试策略

- `SoloGuardLibraryTests`：今日完成状态与昨日缺失判断。
- `StreakCalculatorTests`：连续签到计数。
