# SlowCard 设计文档

> 状态：已采纳  
> 版本：1.1.0  
> 更新时间：2026-11-14

## 1. 产品定位

SlowCard 不发送邮件、不分享内容、不上传卡片。它用延迟解锁把当下的想法封存起来，让用户在未来某天重新看见自己。

**副标题**：慢递明信片  
**Bundle ID**：`com.pocketapps.slowcard`

### 目标

- 用一个清晰的核心动作解决真实场景。
- 数据只保存在本机，隐私边界在首启说明中说清楚。
- UI 能表达空态、进行中、完成、失败和恢复状态。
- 单元测试覆盖核心状态机和过滤器。
- 不把业务逻辑泄漏到共享 Package。

### 非目标

- 不做云后端。
- 不做账号体系和跨设备自动同步。
- 不引入和核心体验无关的复杂权限。
- 不做广告、推荐或数据采集。

## 2. 用户与真实场景

用户正在处理一件烦心事，写下 30 天后的期待。到达前内容不可见；到达日收到本地通知，打开后可以收藏或归档。

### 典型流程

1. 首启说明 → 选择提示 → 写卡片 → 选解锁时间 → 保存并调度提醒。
2. 到达日打开内容，可收藏；未收藏的已收到卡片进入归档。
3. 删除卡片会取消到达提醒并使用确认弹层。

## 3. 信息架构

两栏 Tab：**明信片**、**设置**。明信片页承担列表、过滤和新建；设置页解释隐私与提醒。

## 4. 数据模型

- `SlowCardModel`：卡片 ID、标题、内容、创建时间、解锁时间、收藏状态。
- 派生状态：`traveling` / `received`。

## 5. 关键交互与状态

- 生命周期：`traveling → received`。
- 收藏：独立布尔状态，不影响生命周期。
- 过滤：全部 / 在路上 / 已收到 / 收藏 / 归档。

## 6. 错误与边界处理

- **通知权限拒绝：卡片仍在解锁时间后可见。**
- **内容误删：删除前必须确认。**
- **数据迁移：未来新增字段需评估 SwiftData migration。**

## 7. 隐私与数据边界

- 卡片标题、内容和解锁时间保存在本机 SwiftData。
- 到达提醒为本地通知。
- 不发送邮件，不分享内容，不上传卡片。

## 8. 测试策略

- `SlowCardLibraryTests`：全部、在路上、已收到、收藏和归档过滤。
- `SlowCardModelTests`：卡片生命周期状态。
